# /delete-comment

The repo bans code comments (`docs/adr/0001-no-code-comments.md`).
`COMMENT_DEBT` in `tools/lib/comments.mjs` records the ones still allowed,
per file, and `verify-content` fails if a count goes up or down without the
table following. This skill clears comments one sort at a time.

## 1. List what is left

```sh
node -e "import('./tools/lib/comments.mjs').then(({ sourceFiles, findComments, kindOf }) => { const fs = require('fs'); for (const f of sourceFiles('.')) for (const c of findComments(fs.readFileSync(f, 'utf8'), kindOf(f))) console.log(f + ':' + c.line + '-' + c.endLine + '  ' + c.text.replace(/\s+/g, ' ').slice(0, 100)); })"
```

If `$ARGUMENTS` names a file or folder, keep only those lines. A comment
in generated output goes from its generator too, or the next run brings it
back.

## 2. Sort each comment

Read the code next to each comment, and open other files when it points at
them. Put it in exactly one group:

| Group | Test | Action |
| --- | --- | --- |
| Tautology | It says what the code already shows: a section label, a restated function name, a usage line for a script whose name says it. | Delete. |
| Stale | It names code, counts, files or behaviour that are no longer true. Check before you say so. | Delete. |
| Excuse | It lets a shortcut stand: "for now", "checked by hand because", duplicated logic kept in step by a comment, a known gap with a fix someone could do. | Delete, and file an issue. |
| Decision record | It records a choice someone would undo without knowing why: a 302 not a 301, round up not to nearest, a browser quirk worked around. | Delete, and move it into an ADR. |

A comment that is partly stale but carries a true decision is a decision
record: write the corrected decision. A sound trade-off is a decision, not
an excuse. Before deleting, grep for anything that reads the comment (a
parser, a generator, a check); if something does, change that too.

## 3. Move decisions into ADRs

- Find the ADR for the topic in `docs/adr/README.md` and add a numbered
  entry. Start a new ADR only for a topic none covers, and add it to the
  index.
- Name the file and the function or constant the decision governs, so a
  search by name finds it.
- If `CLAUDE.md` already states the rule, add `(CLAUDE.md §N)` instead of
  restating it at length.
- Write it in plain English: short words, active voice, no em dashes, cut
  every word you can. Code names stay exact.

## 4. File excuses as issues

Search open issues first, so you do not file one twice. One issue per
shortcut, even if several comments excuse it. Say what the shortcut is,
where (`file:line`), and what the fix would be. End the body with:

```
---
_Generated by [Claude Code](https://claude.ai/code)_
```

## 5. Delete and lower the ratchet

- Remove each comment. When it sits on lines of its own, remove those
  lines; when it trails code, remove the comment and the spaces before it.
  Leave no doubled blank lines.
- Lower each file's number in `COMMENT_DEBT` to its new count, and remove
  the entry at 0. Never raise a number.
- Run `npm test`. Every check must pass, `verify-content` first.

## 6. Report

Give counts per group, the ADRs you changed, the issues you filed, and the
lines shed (`git diff --shortstat`).
